Claude Code plugin · for Optimizely teams

Ship Optimizely features like a team.

One agent holding a whole feature reviews its own work. crew splits the job the way your team does: a lead that plans and delegates, specialists that know the CMS they work in, and guardrails in code that keep every lane honest until one review gate says go.

The crew

A lead, and a specialist per lane.

lead plans, waits for your go-ahead, then delegates each step. It writes no production code and is the only agent that touches git.

leadPlans · delegates · commits

Keeps a written plan with acceptance criteria and commits each step once it passes.

backendBackend

Server code for your stack, with the Optimizely skill for your CMS version.

frontendClient-facing layer

Views and components, including Razor markup in server-rendered mode.

unit-testsUnit tests

Backend tests, plus frontend component tests when a tool is configured.

e2eEnd-to-end

Browser tests with Playwright or Cypress.

visual-reviewDesign · read-only

Checks the build against the design and names the token, not just the pixel.

generalistExpress lane

Small, low-risk changes across lanes, without the full ceremony.

incident-triagePost-merge · read-only

Traces a production signal to the code and the suspect commits.

debt-scoutTech debt · read-only

Scouts a scope you name and returns ready-to-paste debt pointers.

Commands

Or open a claude --agent crew:lead session and just describe the work.

  • /crew:initOnce per project: record the stack, the build, test and lint commands, and the formatters.
  • /crew:featurePlan, delegate, build, and stop at the review gate.
  • /crew:reviewGO or NO-GO: code, security and design review, plus build, test and lint.
  • /crew:prPush the branch and open the pull request. The only way out of the machine.
  • /crew:addressRoute review comments and CI failures back to the crew, then run the gate again.
  • /crew:debtFix one debt pointer: a suppression, an analyzer rule, a package upgrade. Beta
  • /crew:triageA bug report, trace or alert → the code and the suspect commits.
  • /crew:loopRun the lead again each tick until the plan's exit conditions are met.
Guardrails

Hooks, not promises.

A prompt is a suggestion to a model. These run in the harness before each tool call, so a worker cannot talk its way past them.

  • One pair of hands on gitOnly the lead runs git. Workers never do.
  • No commits on the base branchWork happens on a feature branch the lead creates.
  • Writes stay in laneEach worker edits only its own files, and shell writes that would route around the guard are refused.
  • Destructive commands refusedDestructive rm, force-push and writes into .git/ are blocked.
  • Guards fail closedWhen a guard cannot read its input, it blocks.
  • Nothing leaves on its ownNo push and no pull request until you run /crew:pr.
Requirements

Bring a repo. That's it.

  • Claude CodeCLI, desktop or IDE extension, with plugin support.
  • A git repositorycrew branches and commits its work.
  • Optional MCP serversPlaywright, Figma, and GitHub or Azure DevOps unlock visual review and PR workflows. Everything else works without them.
